# 04. 基本スタッツの自動検出

実施日: 2026-09-26

## 判定の流れ

```
スコアボード OCR ──▶ 得点の変化(時刻・チーム・1/2/3点)─────────────┐
                                                               ├─▶ イベント ─▶ スタッツ
ボール軌跡 + 選手トラック + チーム ─▶ ボール保持区間 ─▶ シュート試投 ─┘
                                        │
                                        └─▶ リバウンド / アシスト / ターンオーバー
```

| イベント | ルール(`wbt.events`) | 根拠 |
|---|---|---|
| 得点 | スコアボードの得点が増えた時刻・チーム・増分(1=FT、2=2P、3=3P) | OCR |
| ボール保持 | ボールが選手の箱の上部〜膝の範囲に 3 フレーム(0.3 秒)以上ある。3 フレームまでの見失いは許容 | ボール、選手トラック |
| シュート試投 | 保持が解けてから 2.5 秒以内に、ボールがリングの近く(キーフレーム基準 70px × ズーム率)に達する。持ったままリング付近にいる場合は除く | ボール、リング位置(動的ホモグラフィで各フレームに写したもの) |
| 成否 | 試投の −1〜+6 秒に同じチームの得点が 2 点以上増えれば成功(得点表示の更新遅れを考慮) | 試投、OCR |
| リバウンド | 失敗から 6 秒以内に最初に保持したチーム。シュートと同じチームならオフェンスリバウンド | 保持 |
| アシスト | 成功シュートの直前の保持区間が同じチームの別の選手で、その間隔が 3 秒以内 | 保持 |
| ターンオーバー | 保持チームが相手に変わり、その間にシュート試投も得点もない(間隔 3 秒以内、同じショット内) | 保持 |

- 映像で試投を捉えられなかった得点も、スコアボードから成功シュート(またはフリースロー)として数える
- フリースローは失敗を検出できない(フリースロー時はサイドラインカメラに切り替わることが多く、解析対象外のため)
- 選手の個人識別はしないため、スタッツはチーム単位。イベントには画面上のトラック ID を参考情報として付ける
- ルールの動作は、合成データの単体テストで確認している(`tests/test_events.py`: パス→シュート成功→アシスト、失敗→ディフェンスリバウンド、スティール→ターンオーバー、得点後の保持交代はターンオーバーにしない、など)

## 既製モデル(COCO)での結果: Japan v Poland(82 秒)

`python scripts/analyze.py <video> --profile ottawa2026 --out runs/analysis/jpn_pol`(yolov8s、10fps で解析、CPU で 478 秒)

| 項目 | 結果 |
|---|---|
| 広角ショット | 797 フレーム中 469(47.9 秒分)。サイドラインカメラ・クローズアップ・広告の区間は除外 |
| 得点 | 映像中の得点変化 2 回(JPN 2→4、POL 4→6)を、チーム・点数とも正しく検出(2/2) |
| 試合時計 | 160 回の読み取りのうち 131 回で時間的に整合する値を採用(残りは読めない・整合しないため不採用。誤った値の採用はなし) |
| 選手 | 広角ショット1フレームあたりの選手数の中央値 JPN 4 / POL 3(実際は各5)。ゴール下の密集で検出漏れ |
| ボール | 広角ショット 469 フレーム中 28 フレーム(6%)でしか検出できず |
| 映像からのイベント | ボール保持区間が 2 つしか得られず、シュート試投・リバウンド・アシスト・ターンオーバーは検出されなかった |

**結論**: スコアボード由来の得点は既製モデルのままでも正しく取れる。映像からのイベント判定はロジックとテストは揃っているが、
入力となるボール検出が足りない。ボールを重点的にアノテーションした自前モデル(P2b)への差し替えが次の前提条件になる。

## 評価の方法(自前モデルに差し替えた後に実施)

1. 正解イベントを作る: 公式のプレーバイプレー(試合時計つき)を入手し、スコアボード OCR の試合時計で動画の時刻に対応付ける。入手できない場合は動画を見て手で数える
2. `python scripts/eval_events.py runs/analysis/<game>/analysis.json data/gt/<game>_events.json` で、種別・チームが一致し時刻差 2 秒以内のものを正解とみなして、種別ごとの適合率・再現率を出す
3. 評価対象の試合は、学習データ(アノテーション)に使っていない試合にする
