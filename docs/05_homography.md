# 05. 放送映像の動的ホモグラフィ(コート座標変換)

実施日: 2026-09-26

## 課題

選手の位置をコート上の座標(m)で扱うには、画像座標→コート座標の変換(ホモグラフィ)が必要になる。
固定カメラなら一度校正すれば済むが、中継映像のカメラは試合中ずっとパン・チルト・ズームするため、
**フレームごとに変換を求め直す**必要がある。さらに、コートのラインは木目の床に白線で描かれていて映像上では薄く、
コート中央付近ではラインの交点がほとんど見えない。

## 方式: 回転のみのカメラモデル+キーフレーム照合

中継のメインカメラは、位置を固定したまま向きとズームだけを変える。このときカメラ中心が動かないため、
**2枚の画像の間の対応は、写っている物の奥行きに関係なく1つのホモグラフィで表せる**(H = K₂ R K₁⁻¹)。
これを使うと、コートの校正は数枚のキーフレームで1回行うだけでよく、各フレームではキーフレームとの位置合わせだけを行えばよい。

```
コート座標 ──H_court(校正, 会場ごとに1回)──▶ キーフレーム画像 ◀──G_t(特徴点照合, フレームごと)── フレーム t
```

1. **キーフレームの校正**(`scripts/calibrate_keyframe.py`、`wbt.calibration`)
   - 会場ごとに、左ゴール付近・右ゴール付近・コート中央の3枚をキーフレームとして選ぶ
   - コート上の既知点(制限区域の角など)の画像座標を指定する。さらに、交点が見えない場所では
     **「この画像点はサイドライン上にある」という線上の拘束**も使い、点とラインの両方の残差を最小化する(scipy の least_squares)
   - 選手とスコアボードを除いた領域の SIFT 特徴点を保存する
2. **フレームごとの位置合わせ**(`wbt.camera.CameraTracker`)
   - 選手の箱とスコアボードを除いた領域から SIFT 特徴点を取り、RANSAC でホモグラフィを推定する
   - 通常は直前のフレームとの対応を連鎖させる(隣接フレームは見た目が近く、インライアが数百点取れる)
   - ドリフトを抑えるため、15フレームごととショット切替時に**キーフレームへ直接照合し直す**
   - どのキーフレームにも照合できないフレーム(サイドラインカメラ、クローズアップ、リプレイの別アングル)は「広角ショットではない」と判定する。**位置合わせの成否が、そのままショット種別の判定になる**
3. **座標変換**
   - 選手の接地点(箱の下端中央)→ コート座標: `H_court⁻¹ · G_t`
   - リングは床面上にないが、回転のみのカメラモデルなら画像間の対応として正しく写せるため、キーフレームで指定したリング位置を各フレームに写す(シュート判定に使う)
   - 別のキーフレームで指定したリングも `H_court_k · H_court_j⁻¹` で現在のキーフレームの画像に移せる

## 途中で分かったこと(設計の変更点)

| 試したこと | 結果 | 対応 |
|---|---|---|
| 左右のゴール付近の2枚だけを、制限区域の4隅で校正 | 校正に使った範囲は正確だが、コート中央では約140pxずれた(4点が片側に偏っており、外挿で誤差が拡大) | キーフレームを3枚にし、サイドラインの線上拘束を追加 |
| キーフレーム同士を特徴点照合でつないで一括校正 | キーフレーム間の重なりが小さく、インライアが28〜39点しか取れず不安定。無関係な画像同士が誤って対応付いたケースもあった | 一括校正はやめ、キーフレームごとに独立に校正 |
| コート中央の校正にセンターサークルを使う | 中央ロゴの白い円はセンターサークル(半径1.8m)ではなかった。半径を未知数として推定すると2.3m | ロゴ円を半径2.32mの円として扱い、サイドラインの線上拘束と組み合わせた |

## 評価

校正に使っていないフレームで、制限区域の角(7点)の画像座標を目視で読み取り、変換結果と比べた
(`python scripts/eval_homography.py docs/results/homography_checkpoints.json`)。

| フレーム | 照合したキーフレーム | インライア | 画素誤差(平均 / 最大) | コート上の誤差(平均 / 最大) |
|---|---|---|---|---|
| 1450(左側、校正フレームから約20秒後) | left | 238 | 8.1 / 16.6 px | 0.12 / 0.17 m |
| 0(右側) | right | 368 | 13.5 / 22.8 px | 0.15 / 0.30 m |
| 全体(7点) | | | 10.4 / 22.8 px | **0.13 / 0.30 m** |

- 校正時の残差: 点 2〜9px、線上拘束 0.06m 以内
- 車いす1台の幅(約0.7m)より十分小さく、位置のヒートマップやスペーシングの計算には十分な精度
- 読み取り自体の誤差(数px)を含む。最初の評価では読み取りを誤って誤差を過大に出していたため、2倍に拡大して読み直した

## 限界と今後

- キーフレームの校正は手作業(1会場あたり3枚)。会場が変わるたびに必要になる。コートキーポイントの検出モデルを学習すれば自動化できる
- カメラ位置が動く中継(移動カメラ、別の固定カメラへの切り替え)は、回転のみのモデルの前提から外れるため扱えない。現状はショット判定で除外している
- 評価点は7点と少ない。長い試合映像で評価点を増やす
