# 開発計画

最終更新: 2026-09-26

CLAUDE.md の「機能ロードマップ」を、実行できる単位(フェーズ・タスク・完了条件)に分解したもの。
実装を進める中で実態と合わなくなった箇所は随時書き換え、末尾の変更履歴に記録する。

## 前提

- 開発者は1人。工数は「人日(集中して作業できる1日)」で見積もる。カレンダー上の日程は稼働時間が決まり次第追記する
- ローカルはGPUなし(Ryzen 5 5625U)。推論・前処理はローカルCPUで行い、**学習は Google Colab / Kaggle の無料GPUを使う**
- 映像は YouTube の試合映像を画面録画したもの。学習・評価用データは**試合単位で train/val/test を分割**する(同じ試合のフレームが学習と評価の両方に入ると精度が過大評価されるため)
- 【ユーザー作業】と書いたタスクは、アカウントや手作業が必要なため開発者本人が行う(映像の録画、アノテーション、Colab での学習実行、クラウドへのデプロイ)。それ以外はツール・コード側で先に用意し、本人の作業結果を差し込むだけで動くようにしておく

## 実行順

検出モデルの差し替えを前提に、パイプラインは既製モデル(COCO)で先に最後まで通す。自前モデルの学習(P2 の【ユーザー作業】部分)は並行して進め、できた時点で重みを差し替えて精度を測り直す。

1. P1 外部設計
2. P2a データセット作成・学習のツール整備
3. P3 ショット判定・トラッキング・チーム識別・カメラ運動推定
4. P5 コート座標変換(基準フレームの校正)… リング位置がシュート判定に必要なため P4 より先に行う
5. P4 スタッツ検出(スコアボードOCR、イベント判定)
6. P9 戦術分析のパイプライン部分(ターンオーバー、スペーシング)
7. P6 API → P7 フロントエンド → P8 Docker化
8. P10 ポートフォリオ化
9. P2b(並行)映像収集・アノテーション・学習 → 自前モデルに差し替えて P3〜P5 の評価をやり直す

- [x] 既製YOLOv8 n/s/m による person 検出ベースライン → `docs/01_baseline_yolov8.md`
- [x] 既製モデルでのボール検出(COCO `sports ball`)の確認、ベースライン文書への追記 → 広角ショットでは25枚中2〜4枚しか検出できず、自前学習が必須
- [x] git 初期化、ディレクトリ構成の整理(`src/wbt` パッケージ化+`pyproject.toml`、`scripts/` は実行用の薄いラッパー)
- [x] 学習用GPU環境(Colab / Kaggle)で ultralytics の学習が回ることを確認(`notebooks/00_colab_gpu_check.ipynb`、Colab T4 で確認済み)

**完了条件**: ボールを含むベースラインが記録され、GPU環境で学習を試せる状態になっている

## P1 外部設計

- [x] システム構成図、パイプライン構成、データ形式(会場プロファイル、`analysis.json`)、API、画面設計、技術スタック → `docs/design.md`
- [x] 動画の入力方式: アップロードのみ(YouTube URL からの取得は利用規約上の理由で実装しない)
- [x] コート座標変換の方式: 回転のみのカメラモデルを使い、基準フレームの校正をフレーム間ホモグラフィで伝播する

**完了条件**: `docs/design.md` があり、P3以降のモジュールがどのデータを受け渡すかが決まっている

## P2a データセット作成・学習のツール整備

- [ ] アノテーション指針 `docs/annotation_guide.md`: クラス(`player`=選手+車いす全体、`ball`、`rim`、`referee`)、箱の付け方、遮蔽時の扱い、ベンチ・観客は付けない
- [ ] 広角ショットのフレームだけを抽出するスクリプト(P3 のショット判定を流用)
- [ ] 既製モデルの出力を下書きラベル(YOLO形式、CVAT に読み込める zip)として書き出すスクリプト
- [ ] 試合単位で train/val/test に分割し、ultralytics の `data.yaml` を作るスクリプト
- [ ] Colab 用の学習・評価ノートブック(クラス別 mAP、既製モデルとの比較、学習曲線の保存)

**完了条件**: 本人が「録画 → 抽出 → 下書き → CVATで修正 → 分割 → Colabで学習」を手順書どおりに実行できる

## P2b 映像収集・アノテーション・学習【ユーザー作業】(→ M1)

- [ ] 試合映像を5試合程度集める(男女、会場、ユニフォーム色の組み合わせがばらけるように)。画面録画に広告が入らないようにする(入った場合は区間をカット)
- [ ] 第1弾: 約300枚をアノテーション(ボールは既製モデルがほぼ使えないため、広角ショットでのボールを重点的に確保する)
- [ ] Colab で YOLOv8(s を基本に n/m と比較)をファインチューニング。ボール向けに imgsz 1280 以上、タイル分割推論(SAHI等)も比較する
- [ ] test セットで評価: クラス別 mAP50 / mAP50-95、密集シーンでの player 再現率。既製モデル(person→player として比較)との差分を示す
- [ ] 誤りを分析し、苦手なシーンを中心に約300枚を追加 → 再学習(2周目)
- [ ] 学習ログ・評価結果を `docs/02_dataset.md`、`docs/03_finetune.md` にまとめる
- [ ] 学習済みの重みでパイプラインを動かし、P3〜P5 の評価をやり直す

**完了条件**: 自前モデルが test セットで既製モデルを上回り、その根拠(指標・学習曲線・誤り例)が文書化されている

## P3 ショット判定・トラッキング・チーム識別・カメラ運動推定

- [ ] 検出モジュール: モデルごとのクラス対応表で `player/ball/rim/referee` に正規化する(COCO モデルと自前モデルを差し替え可能にする)
- [ ] ショット判定: 広角の試合ショットかどうか(クローズアップ、リプレイ、観客席、暗転、広告などを除外)。低い位置のサイドラインカメラは当面は対象外とする
- [ ] 選手トラッキング: ByteTrack(ultralytics 組み込み)。ショットが切り替わったらトラックをリセットする。コート外の人物(ベンチ・観客)を除外する
- [ ] ボール軌跡: フレームごとの候補から軌跡として一貫するものを選び、途切れた区間を補間する
- [ ] チーム識別: player の胴体部分の色特徴をクラスタリングする(試合ごとに2チーム+審判)
- [ ] カメラ運動推定: 隣接フレーム間のホモグラフィ(選手・スコアボード領域を除いた特徴点)と、基準フレームへの再照合
- [ ] 評価: 30秒程度のクリップにトラッキング正解を付け、IDF1 / ID切り替え回数を測る【正解付けはユーザー作業】

**完了条件**: 広角ショット区間で、選手ID・チーム・ボール軌跡・カメラ運動が時系列データとして出力される

## P4 基本スタッツの自動検出

- [ ] スコアボードOCR: 試合時計・得点を読み取り、時間方向の整合チェックで誤読を補正する
- [ ] ボール保持者の推定(ボールと選手の位置関係、保持の継続時間)
- [ ] イベント判定(`docs/design.md` 2.2 のルール): 得点、シュート試投・成否、リバウンド(攻守)、アシスト
- [ ] リプレイ区間の除外(P3 のショット判定を利用)による二重カウントの防止
- [ ] 評価の仕組み: イベントの正解ファイル形式と、イベント種別ごとの適合率・再現率を出す評価スクリプト。正解は公式ボックススコア/プレーバイプレー、なければ手動で数える
- [ ] CLI: 動画を入力すると `analysis.json` とスタッツ表(CSV)を出力する
- [ ] `docs/04_stats_detection.md` に判定ロジックと評価結果をまとめる

**完了条件**: 評価対象の試合で、得点・シュート試投を中心に精度が数値で示され、CLI で再現できる

## P5 コート座標変換

## リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| ボール検出の精度が出ない(小さい、ブレる、遮蔽される) | P4 のすべての判定 | アノテーションでボールを重点的に増やす、高解像度で推論する、軌跡の補間、得点変化(OCR)との併用 |
| アノテーション工数が膨らむ | P2 が長引く | 既製モデルの出力を下書きにする、苦手シーンを中心に追加する方式にする |
| 公式ボックススコアが入手できない試合がある | P4 の評価 | 入手できる試合を評価用に優先して選ぶ。入手できない場合は手動で数えた正解で代替する |
| 動的ホモグラフィが安定しない | P5・P9 | 対象を広角ショットに限定、基準フレームへの定期的な再照合、失敗したフレームは座標なしとして扱う |
| 放送カメラが回転のみのモデルから外れる(カメラ位置が動く、別カメラに切り替わる) | P5 | ショット判定で別アングルを除外する。照合の誤差が大きい区間は座標変換を行わない |
| CPU推論が遅く、Web公開で実用にならない | P8 | 解析済みデモを中心に公開する、推論間隔を間引く、ONNX 化で高速化する |
| YouTube利用規約(動画のダウンロードや再配布の制限) | P7・P8 | アップロードのみ対応(P1で決定)。学習データの画像や映像そのものを公開リポジトリに含めない |
